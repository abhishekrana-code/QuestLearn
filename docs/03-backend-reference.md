# 3. Backend reference

Root: `questlearn-backend/src/main/java/com/questlearn`

The backend is organised by responsibility, not by feature. This page walks the
packages in dependency order and lists **every class and every declared function**,
including private helpers that carry a rule worth knowing. Constructors generated by
Lombok and accessors generated by records/JPA are not repeated; they do nothing
beyond their name.

## 3.1 Package map

| Package | Files | Responsibility |
| --- | ---: | --- |
| `com.questlearn` | 1 | Spring Boot entry point. |
| `config` | 10 | Startup seeding, security wiring, mail/media choice, scheduling, OpenAPI. |
| `controller` | 13 | HTTP surface. |
| `dto` | 67 | Immutable request/response records. |
| `email` | 5 | Delivery adapters behind one interface. |
| `exception` | 3 | Typed failures and the single JSON error handler. |
| `mapper` | 1 | Entity → DTO. |
| `model` (incl. `service.media`) | 22 + 4 | JPA entities, enums, media drivers. |
| `repository` | 16 | Spring Data interfaces. |
| `security` | 4 | JWT, one-time tokens, request tracing. |
| `service` | 28 | Business rules and transactions. |
| `util` | 1 | Email normalisation. |

## 3.3 `config` — startup and wiring

### `DataInitializer implements ApplicationRunner`

Seeds the demo. Runs only when the expected marker data is missing, and backfills
features added after a database was first created. It is safe to restart repeatedly.

| Function | What it does |
| --- | --- |
| `run(ApplicationArguments)` | Entry point. Decides whether this is a fresh database, resolves the demo password, then calls `seedDemoData`. |
| `seedDemoData()` | Creates the five demo accounts (admin, instructor, three students), the "Full-Stack Web Engineering Quest" with six linked nodes and quizzes, the second course "Data Structures Detour", rival progress, and a demo lesson video. Writes a `DemoCredential` row when it generated the password. |
| `resolveDemoPassword(boolean freshDatabase)` | Applies `DemoPassword.resolve`: use `DEMO_PASSWORD` if set, generate one only on a fresh database, otherwise leave existing hashes alone. |
| `demonstrationPasswordNote()` | Produces the one-time console message that tells an operator where to find the generated password — without logging the password on later starts. |
| `syncDemoPasswords()` | If the configured/resolved password changed, re-hashes it for all demo accounts so the published demo logins stay true. |
| `seedSecondCourse()` | Seeds "Data Structures Detour" with its own node chain, so the catalogue and the AI/leaderboard screens have more than one shape of course. |
| `seedDemoAnnouncements()` | Posts one course-wide note and one class note to the demo course, creating the "12B Web Engineering" class, enrolling the demo student and adding them to the class, so the notices channel has content on a fresh clone instead of only its empty state. The welcome note is the marker, so it seeds once. |
| `backfillDemoAttempts()` | For databases seeded before attempt history existed, adds plausible attempts so the performance page is not empty. |
| `backfillAttempts(User student)` | Writes the per-node attempts for one demo student. |
| `attachDemoVideo()` | Stores a bundled 12-second clip through `MediaStorageService.storeNamed` and attaches it to one node, unless that node already has a video. |
| `seedRivalProgress()` | Gives Mira and Sam different progress so the demo leaderboard is not a three-way tie. |
| `seedRival(String email, List<Module>, Map<String,Integer>)` | Seeds one rival's completed nodes and scores. |
| `seedUser(name, email, role, totalXp, streak, lastActivity)` | Creates a demo account if the email is absent; computes the level from XP. |
| `seedModule(course, parent, title, xp, …, position, order)` | Creates one node with its tree coordinates and link. |
| `quiz(module, type, passingScore, payloadJson)` | Parses a JSON payload and attaches a quiz. |
| `seedProgress(user, module, status, score)` | Convenience overload that delegates with no completion time. |
| `seedProgress(user, module, status, score, completedAt)` | Creates/updates a progress row with attempts and completion time. |
| `sections(headingOne, bodyOne, headingTwo, bodyTwo)` | Builds the lesson `sections` array used by seeded nodes. |

| Function | What it does |

needed, and pick a status code. All paths are under `/api/v1` (declared per class).

## 3.6 `service` — business rules

### `AuthService`

| Function | What it does |
| --- | --- |
| `register(RegisterRequest)` | Resolves the role (default `STUDENT`), rejects `ADMIN`, enforces the instructor/student invite code, normalises the email, rejects duplicates, stores a BCrypt hash, issues a verification link, returns a token. |
| `login(LoginRequest)` | Checks the lockout, finds the user, compares the hash, records failure/success, returns a token. The same message is used for unknown email and wrong password. |
| `changePassword(principal, request)` | Verifies the current password, refuses reuse, hashes the new one, bumps `tokenVersion`, returns a fresh token. |
| `setDeadlineEmails(principal, enabled)` | Writes `notify_deadlines` and returns the user. |
| `currentUser(principal)` | Loads and maps the account. |
| `loadUser(Long)` | User or 401 "Account no longer exists". |
| `assertStudentInviteCode(supplied)` | When a code is configured, requires a constant-time match. When none is configured and `require-student-code` is true, fails closed; otherwise open. |
| `normaliseCode(String)` | Trim + lower-case, so case and spaces do not matter. |
| `constantTimeEquals(configured, candidate)` | `MessageDigest.isEqual` on UTF-8 bytes. |
| `assertInstructorInviteCode(supplied)` | Empty configured code disables instructor self-registration; otherwise constant-time match. |
| `toAuthResponse(User)` | Token + `Bearer` + expiry + user DTO. |

### `ProgressService`

| Function | What it does |
| --- | --- |

### `QuizService`

| Function | What it does |
| --- | --- |
| `sanitize(Quiz)` | Deep-copies the payload and removes the answer key: MC removes `correctIndex` and `explanation`; code order removes the explanation and shuffles lines; drag-drop replaces `pairs` with separate `items`/`targets`. Returns `null` for no quiz. |

| `evaluateCodeOrder(payload, answers)` | Requires an order of the same length; one point per correct position. |
| `evaluateDragDrop(payload, answers)` | One point per left whose mapped right is canonical. |
| `explanations(Quiz)` | Extracts the explanation text **after** grading: one per MC question, or the single explanation for the other types. |
| `percentage(correct, total)` | Rounded percentage; 100 when total ≤ 0. |

## 3.12 `util`

`Emails.normalise(String)` trims and lower-cases an address. Every path that stores or
looks up an email uses it, so `User@Example.com` and `user@example.com` are one
account. The private constructor makes the class non-instantiable.

## 3.13 Cross-cutting conventions

- **Errors are values.** Services throw `ApiException` factories; the handler owns the
  JSON shape. Controllers never build error bodies.
- **Ownership beats role.** A role annotation says "an instructor may author"; the
  service still checks "this instructor owns this course".
- **One transaction per command.** A completion, roster import, account deletion or
  course duplication is atomic. Read methods are marked `readOnly`.
- **Entities stay inside.** Only DTO records cross the HTTP boundary, which keeps
  lazy associations from leaking and keeps the wire contract stable.
- **JSONB is schemaless but not unvalidated.** Lesson content is flexible; quiz
  payloads are validated before they are stored and sanitized before they are read.
- **Nothing expensive is trusted to the browser.** XP, levels, pass/fail, deadline
  state and leaderboard rank are all server-derived.
